# C5 box controller identification — 14 November 2026

**Current USB bring-up:** the initial exact-unit image was flashed and verified. Its first service response exposed a six/eight-byte MAC API defect; the corrected image is now flashed and hash-verified after a manual BOOT reconnect. After normal RESET, the corrected factory identity, repeated USB opens and stop/reboot persistence passed. Revision 2 and both service receipts survived; storage remains healthy with outputs reported disabled. No provisioning or peripheral activation has occurred. [Build, failed check and recovery checkpoint](../verification/m4/c5-usb-bringup.md)

Rafa connected the C5 by USB with peripherals and external power disconnected. ROM inspection identified **ESP32-C5HF4 revision 1.0**, 4 MiB embedded flash, no embedded PSRAM, a 48 MHz crystal and native USB-Serial/JTAG. Base MAC is `02:00:00:00:fe:03`; the explicit observed port was `/dev/cu.example-usb`, USB `303a:1001`. Rediscover the port and verify the base MAC before any later write. [Machine record](c5-identification.json) · [ROM output](../verification/m4/c5-rom-identification.log)

The ROM read used esptool 5.6.0 and its reset sequence, without writing flash. A subsequent RAM-only read stub saved all 4,194,304 bytes to an ignored owner-only backup; its checksum and permissions are recorded in the machine record. No firmware installation, NVS initialization, provisioning or peripheral activation had occurred at that initial identification checkpoint. The later installation is recorded above. This does not establish application USB reset behavior.

Rafa supplied the marking `2BB77-espc5-32e` and a [front photograph](../verification/m4/c5-front.jpg). The photograph shows an external antenna cable connected to the module, two USB-C connectors, BOOT/RESET buttons and a red illuminated indicator. Its module marking/layout is consistent with DOIT ESPC5-32E-H4. The manufacturer-authored [ESPC5-32E manual, version 1.0](https://atta.szlcsc.com/upload/public/pdf/source/20251016/AE26C73F5F73E1BD024C1C95B3A92329.pdf) lists the H4 module with 4 MiB flash, no PSRAM and a U.FL antenna connector. This supports a module identification; it does not identify the carrier PCB or prove its header routing. No GPIO assignment is inferred from a similar Espressif DevKit.

Rafa subsequently identified the carrier marking as **ESP32-C5-KitC-A V1.3**. The seller gallery shows the same rear marking and front layout. Its photographed header labels, checked against the DOIT module manual and Espressif datasheet, support GPIO8/9/10/23 for coil outputs, GPIO6 for LED data and GPIO1 for the optional setup ADC. Some unrelated labels in the seller infographic conflict with the board photo. The `box-c5-candidate` profile remains unverified and `test-box` is synthetic and ineligible for flashing. [Seller profile review](c5-seller-profile-review.md)

The selected pin labels support a separate, unit-bound USB-only profile with motor outputs held low, LED and ADC disabled, and peripherals and external power disconnected. Trace continuity, inactive levels through reset, carrier power routing and source isolation, antenna rating, and the loaded electrical and mechanical checks remain open. [Power and wiring](power-and-wiring.md) · [Calibration](box-calibration.md)

Rafa directed a read-only review of his Home Sensing (CSI) project. Three retained identification/flash logs match this exact MAC to former node **c5-rx-a**. That project supplies working native USB and 4 MiB DIO/40 MHz settings on ESP-IDF 6.0.0, but used no application GPIO. No motor, LED, ADC pin or power-isolation fact is inferred from it. [Source review](c5-csi-source-review.md). The Home Sensing project was not modified.
