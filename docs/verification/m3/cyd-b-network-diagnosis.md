# CYD B connection loss during mixed play and service idle

On November 13, the normal-image mixed round started in maze cell A4 at board version 0. CYD B held role B and the host reported both controllers ready. After B lost ownership, browser A later moved the key to A3 at board version 1. CYD B again went offline and the host paused the game with B unassigned. USB readback observed a null binding on the same boot while service revision 4 remained uninhibited and reported no storage fault. No physical B swipe was confirmed by a board-version advance in this sequence. The server’s 1,500 ms freshness check can pause the game while retaining the owner. The unassigned state establishes that the owner was later cleared. [Mixed-round start](cyd-b-mixed-start.json) · [Freshness check](../../../server/lib/vault/game_session.ex#L1493) · [Ownership revocation](../../../server/lib/vault/game_session.ex#L1621)

After `service.stop` at revision 5, Rafa reported that the display was online, briefly showed a socket transition, then returned online while the screen was untouched. From 19:40:07.676 to 19:40:46.207 UTC, 31 USB polls showed one boot ID, inhibited service and zero storage faults. Three polls recorded a null binding at 19:40:11.491, 19:40:34.786 and 19:40:42.407 UTC. The other polls covered four distinct live connection IDs. Intermittent loss and reconnection therefore occurred during service idle as well as during maze play. [Service-idle samples](cyd-b-network-service-idle-01.json)

## Server diagnostics ready for deployment

`VAULT_DEVICE_SOCKET_DIAGNOSTICS=true` enables warning-level logs at close time. An application-initiated close records the existing numeric WebSocket code and fixed reason. Other terminations record a fixed cause for a peer WebSocket close frame, abrupt transport close, timeout, server shutdown, adapter error, or unknown callback reason. Both include only the numeric binding generation or `unbound` for correlation. The diagnostics omit device identity, headers, frame payloads and raw adapter errors. The close frame, terminal state and gameplay protocol retain their existing behavior. The live instance had no new diagnostics at the time of this review. The endpoint disables code reloading, so the normal start procedure needs a compiled diagnostic server process. An existing authorized BEAM console can explicitly load the module independently of Phoenix's reloader. [Server close logging](../../../server/lib/vault_web/device_socket.ex#L665) · [Termination classification](../../../server/lib/vault_web/device_socket.ex#L165) · [Runtime configuration](../../../server/config/runtime.exs#L58)

`tools/test-server test/vault_web/device_socket_test.exs` passed **51 pure tests and 13 socket tests, zero failures**, including the runtime guard. The additional Bandit tests verify the existing policy close frame, classification of a peer close, omission of payloads and identities, and quiet behavior without opt-in. `mix format --check-formatted lib/vault_web/device_socket.ex test/vault_web/device_socket_test.exs` passed from `server/`. These checks used isolated test stores and a loopback fixture. [Socket tests](../../../server/test/vault_web/device_socket_test.exs#L12)

An abrupt transport close establishes that TCP ended without a WebSocket close frame reaching the server. It leaves the device, network and adapter causes open. The possible transmit-lock contention in the pinned WebSocket client remains unconfirmed and no transport change was made for this diagnosis. In firmware source, the zero-role display message now says **Waiting for connection** when offline or in link error and reserves **No roles authorized** for an online zero-role projection. This wording change had not been flashed at the time of review. ## Diagnostic server deployment

The coordinator compiled the dev application with `mix compile --warnings-as-errors` successfully, then gracefully terminated the isolated bench PID 58637. Its listener and deployment ownership marker disappeared before startup. The guarded diagnostic launcher started PID 82833 with the existing databases/keys, `VAULT_DEVICE_SOCKET_DIAGNOSTICS=true` and info-level logging. `/health` returned `{"status":"ok"}`. The restart retained maze cell A3 and board version 1 in a paused restored session, with no release requested and setup required. Browser A reauthenticated and reclaimed its role. CYD B retained its board boot and service revision 5 and reconnected while inhibited. The new server log is private/ignored `.cache/m3-hardware-server-diagnostics.log`; its current timestamps use local EST, unlike the older UTC server log. No CYD firmware or transport settings changed.

This deployment changes logging level and process/session generation together, so any later stability comparison must not attribute the outcome to a single cause without separate evidence.

## November 13 follow-up

Opt-in server diagnostics now include `role_mask`, `admission_age_ms`, `tokens_after_admit`, and `socket_age_ms`. The mask comes from the credential’s registered roles. On this bench, mask `1` identifies the A-only registration and `2` identifies the B-only registration. The ages measure time since the last admitted application message and since socket initialization. `tokens_after_admit` is the stored balance after the last admission. Later close logs can associate an event with a registered role scope. Earlier `1008 rate_limit` and `transport_closed` entries did not include that scope. [Socket attribution fields](../../../server/lib/vault_web/device_socket.ex#L671)

The loopback regression sends 14 unclaimed heartbeat replies paced by real 100 ms challenges and confirms that each is accepted and a subsequent snapshot request succeeds. A separate connection collects replies to the same number of challenges and flushes them in one write. The server rejects early expired challenges, then closes the compressed delivery with `1008 rate_limit`. The test reproduces a server-side mechanism for burst closure. It does not establish that either physical CYD delivered such a burst or explain the earlier abrupt TCP closures. [Paced and compressed heartbeat test](../../../server/test/vault_web/device_socket_test.exs#L325)

The full `tools/test-server` run passed **199 distinct tests with zero failures**, comprising 51 pure and 148 integration tests. The second ExUnit summary counted 199 tests and listed the 51 pure cases as excluded from that pass. The pure runtime guard also passed. [Archived server regression log](unattended-server-regression.log)

The host assignment menu now filters candidates by registered role and shows a real CYD’s identity to the host. The coordinator deployed that change on isolated bench PID `49692` and verified `/health`. Endpoint startup is recorded in `.cache/m3-hardware-server-assignment.log`. This deployment corrects assignment choices while the intermittent connection fault remains open. [Host assignment filter](../../../server/lib/vault_web/live/host_live.ex#L779) · [Assignment regression](../../../server/test/vault_web/host_assignment_test.exs#L9)

CYD B’s temporary firmware records sticky failure details and send phases so an observed lock wait can be distinguished from a raw send error. The available idle captures did not reproduce a runtime send failure. The later host first-heartbeat fix passed its red-to-green regression and the final 200-test server suite. It addresses an independent stale host label. After deploying that fix and restoring normal CYD B firmware, the quiet-window 60-update load and all 45 USB polls over 90 seconds passed without a device close in the server log. Both-role disconnects were separately observed during compilation; the earlier physical transport/rate-limit cause remains open.
