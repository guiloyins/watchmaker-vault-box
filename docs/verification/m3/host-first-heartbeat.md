# Host first-heartbeat publication

When a controller claimed A before its first accepted heartbeat and B remained unassigned, the host could keep showing **Awaiting controller** for A. The claim published an owned but unseen peer. A subsequent neutral heartbeat updated the binding’s `last_seen_ms` without changing the puzzle’s visible held input or the aggregate readiness flag. The host subscription therefore missed the individual peer’s change to **Fresh**. Existing snapshot coalescing remains in effect. Heartbeats that keep an already-fresh peer fresh do not produce a new revision unless they change existing visible input or readiness. Heartbeat acceptance, lease timing, and projection fields retain their existing rules.
