# Dual-CYD maze disconnect

On November 13, 2026, the host started a fresh maze with physical CYD A and CYD B assigned, fresh, and released. Both panels showed A4 (cell 12), board version 0, with the simulated box armed. Rafa reported, “I touched A and it disconnected.” Rafa subsequently clarified: “Neither. I just picked it up from the table.” No touchscreen input was involved and no move was accepted by the host. The host subsequently showed a paused maze at A4 and board version 0, with A unassigned, B still fresh, and no release requested. [Start](dual-cyd-start.json) · [Host snapshot](dual-cyd-a-disconnect-host.json)

The opt-in bench server log recorded Terminal A's registered role mask (1) on three `transport_closed` events at 23:09:56.973, 23:10:00.411, and 23:10:35.231 UTC. The following 15 USB status reads all reported service revision 5, service exited, no storage fault, and the same boot ID observed after the normal flash. All 15 saw one live binding, different from the postflash readback binding. [USB status capture](dual-cyd-a-disconnect-usb.json) · [Postflash readback](cyd-a-current-normal-usb.json)

These observations establish a lost transport and reassignment requirement within the same device boot. The cause of the transport close remains undetermined. The user confirmed there was no touchscreen input.

## Untouched recovery observations

Two further 45-second USB captures retained one boot and healthy board/calibration flags while A repeatedly retried. SDK 32774 maps to the pinned SDK's nonblocking TCP establishment timeout before the HTTP upgrade request; generic stage 23 / zero-error attempts remain ambiguous. The second capture also retained a generic stage 24 failure from generation 18 at device uptime 128,996 ms, which cannot distinguish an owner watchdog from an undetailed socket close. These captures do not establish a causal link to picking up the board. [Idle 1](cyd-a-disconnect-netdiag-idle-01.json) · [Idle 2](cyd-a-disconnect-netdiag-idle-02.json)

A bounded reachability comparison found 0/3 ping replies from A and 3/3 from B, with the ARP entries still mapped to their reviewed MACs. Phoenix health and its listener were available. Host packet-header capture was unavailable because the operating system denied BPF access; no packet data was captured. These observations motivate connection-path and owner-retirement diagnostics, not a timeout-policy change. [Reachability](cyd-a-disconnect-reachability.json)

A third untouched 45-second interval recovered: all 90 USB samples reported online on one boot/generation (27), with no new failure count. The concurrent host TCP observation saw one established A connection throughout its change samples, receive queue zero, and transient send queue up to 276 bytes. Diagnostic heap watermark was 54,488 bytes, with main/network worker stack low-water reserves 61.5%/59.1%. This is intermittent recovery on a diagnostic image, not a fix or a physical acceptance pass. [Idle 3](cyd-a-disconnect-netdiag-idle-03.json) · [TCP states](cyd-a-netdiag-tcp-states.json)

## Later simultaneous disconnect — 13 November 2026, 18:46 EST

Rafa subsequently reported both devices disconnected before the requested swipe; he tapped each role and both showed paused. The current host snapshot confirms A4/board 0, both real CYDs fresh, paused, no release. A's v2 history retains the same boot and exactly one failure: generation 1, SDK-origin socket close, raw-send phase 6 taking 27 ms, numeric errors zero, no controller retirement reason. It has reconnected as generation 2. The server recorded A and B transport closes only eight milliseconds apart at 18:46:51.214/222 EST, with the latest admitted traffic about 1.1 seconds earlier.

Pinned SDK inspection shows phase 6 can result from a writable-socket timeout before the WebSocket header or after a header write while waiting on payload transmission. Duration and zero errno do not distinguish those paths, so this frame must not be replayed and no deadline policy was changed. A's record cannot determine B's device-side failure cause. The simultaneous host events motivate a shared path check; they do not establish an AP or Mac fault.

The Mac's bounded power log contains no incident sleep/wake event, and an idle-sleep prevention assertion remains held. CYD traffic routes through Wi-Fi `en0`; the detected Ethernet adapter `en5` has no link. The bounded Mac Wi-Fi log did not identify a disassociation or roaming event. A wired-host comparison was initially requested; Rafa subsequently clarified there is no Ethernet cable or adapter and selected Wi-Fi-only ping monitoring.
