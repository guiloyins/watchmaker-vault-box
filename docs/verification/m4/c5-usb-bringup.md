## First installation and identity correction

The guarded first installation succeeded: exact ROM target, base MAC and 4 MiB flash matched. The protected full-flash backup matched its checksum. Live security state and the old partition digest passed the wrapper's checks before bounded initialization of NVS at `0x9000`, size `0xf7000`. Erase readback and all three written image hashes passed. The original CSI partition layout overlapped this new NVS region; the entire original image remains in protected ignored storage. [Initial flash log](c5-usb-initial-flash.log) · [Initial manifest](c5-usb-initial-build.json)

The first USB query received a valid `wrong_device` response naming `factory_d0cf13feffe4`, rather than the expected `factory_02000000fe03`. The pinned ESP-IDF implementation of `esp_efuse_mac_get_default` expands a six-byte factory MAC into eight-byte EUI-64 on this IEEE 802.15.4-capable chip; the application's six-byte buffer was therefore also overrun by two bytes. The box application now calls `esp_read_mac(mac, ESP_MAC_EFUSE_FACTORY)`, whose declared and implemented length is six. Read failure still halts before NVS/service initialization. The CYD targets do not use this C5 path. [Initial response](c5-usb-initial-status.json) · [Corrected startup](../../../firmware/apps/box/main/app_main.cpp)

The corrected full clean target build passed: app **1,037,360 bytes**, SHA-256 `bcaaccf7db7d18831514f7d91ffc9f9b1b585a55702acc67c467c610f897565f`. [Corrected manifest](c5-usb-build.json) · [Build log](c5-usb-build.log). Two subsequent automatic ROM-connection attempts failed with no serial data, before any image writes. The USB descriptor still identifies the same MAC, but a direct service read also timed out. Rafa then performed the manual BOOT-held USB reconnect. The corrected image installed successfully, preserving NVS, and all three written hashes verified. [Successful corrected flash](c5-usb-flash-manual-boot.log). Its first service read remained silent. Rafa pressed normal RESET with BOOT released; the application then responded. The manual-download reset limitation is described by [Espressif](https://docs.espressif.com/projects/esptool/en/latest/esp32c5/troubleshooting.html#leaving-download-mode-in-usb-serial-jtag-mode). [First attempt](c5-usb-flash.log) · [Retry](c5-usb-flash-retry.log). No provisioning or mechanical calibration has been written. Corrected runtime identity, USB reopening and service-record persistence now pass the checks below.

## Acceptance limits

USB service evidence cannot establish actual voltage or inactive levels at the headers. Cold power cycles, hardware stop latency, full retained-storage/Wi-Fi/WSS heap and stack, source isolation, motor/LED/ADC electrical checks and loaded mechanical travel remain unverified. Keep this profile unprovisioned; install the final electrically reviewed profile with the same partitions and preserved NVS before first provisioning.
